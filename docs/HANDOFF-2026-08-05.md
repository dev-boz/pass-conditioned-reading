## The headline

**The pipeline completes end to end, and it replicated on held-out seeds.**

A 1.5B student, given a role-aware compressor and an edit guard, builds a bounded state from a
65,781-token document that an **untrained 3B** answers a cross-module question from — in about 3
draws of 10 — and never destroys the fact once recorded.

## The recorder/reader split — the finding that emerged for free

Replaying ONLY the closing turn on states the 1.5B built itself:

| reader | overall | given the state holds both operands |
|---|---|---|
| student (1.5B, fine-tuned) | 0/10 | **0/3** |
| Qwen2.5-3B (untrained) | 3/10 | **3/3** |
| Qwen2.5-7B (untrained) | 3/10 | **3/3** |
| Qwen2.5-14B (untrained) | 3/10 | **3/3** |
| Claude Haiku 4.5 | 3/10 | **3/3** |

Every reader from 3B to a frontier model answered on **exactly** the same seeds — precisely the
states that truly hold both operands. Not one more, not one fewer. Three consequences:

1. **The state is exactly sufficient.** Where it holds the operands, any competent reader answers;
   where it does not, nothing up to a frontier model recovers them.
2. **Scaling the reader buys nothing past 3B.** All headroom is in the recorder.
3. **The compose boundary is 1.5B→3B**, not 1.5B→7B as GATE-3's seeded-state result implied.

Maintainer's framing, recorded because it is the right one: this is a **ratio** property, not a
smallness claim — 35B-write → 100B-read is the same finding, and it is a cost lever that fell out of
testing rather than a designed result. Caveat also recorded: it may not transfer to the M-NL nuance
work, because there the recorder must record a pattern *before knowing it matters*, and G4 already
showed noticing scales while acting on it does not.

## What worked, and what did not

**Structural interventions worked. Prompt interventions did not — 0 for 5.**

| intervention | layer | result |
|---|---|---|
| role-aware LLM compressor | architecture | operands delivered at level 1 |
| `guard="retain"` (refuse REPLACE that drops literals) | harness | 391 destructive edits blocked; **zero losses**; c1 0/10 → 3/10 |
| mark enforcement (`marked_hard`) | harness | 8 ops refused, losses eliminated |
| p1g `ANTI_GRIND` | prompt | near-negative |
| `noclobber` sentence (x2 runs) | prompt | **below** baseline, and raised detail-loss attempts |
| `selfmark` (model marks its own entries) | prompt | **0** marks in 10 draws |
| `marked_soft` (model shown marks, asked to respect) | prompt | **identical to baseline** |

`marked_soft` is the cleanest negative: same 8/10, the same two losses at the same pass 57, 209
REPLACEs vs 215. Hand-verified live — the rule flagged exactly S36 (the clobbered entry, holding the
table) and S65 (adder + relation). It was shown the flag, told what it meant, and overwrote it
anyway. **At this scale the edit policy must be enforced by the architecture, not requested.**

## Measured mechanisms (all hand-verified)

- **Edit pathology, 3,941 REPLACEs across pyramid draws:** 33% byte-identical no-ops, 26% target an
  entry with <20% lexical overlap with the current view, **37% drop numeric literals the entry
  held**. Of the 3,226 that passed the strict guard and were applied, **1,003 (31%) destroyed
  detail**, 435 of them five or more literals at once.
- **The clobber, caught in the act:** `graded` seed 5 held the full table in S36 for 19 passes, then
  at pass 57 — a view containing *only* declaration-free boilerplate — five REPLACEs fired and S36
  became `routing/manifest78: normalize_parcel...`.
- **The pyramid's own cost:** doubling passes doubles the exposure of everything recorded. The same
  seed under D25 recorded at pass 12 and survived.

## The fixture is the standing constraint

`author_pyramid_views.py --budget-audit`:

```
document                     65,781 tok  (106 modules)
  declaration-free                100 modules -> one 677-tok pattern block
  declaring modules                 6 modules
    their declarations (sigma 1)  1,129 tok
view budget V                   3,000 tok
distinctive content + block     1,806 tok = 60% of ONE view
```

Any compressor good enough to notice the document is a hundred copies of one module puts the entire
distinctive content in the level-1 view — so the three best arms all break the split-fact guard.
**Phase 2's fixture rebuild needs distinctive content exceeding one view budget.** Run the audit
before authoring.

This fixture has now saturated **four** heuristics: compression, recording, salience, and the
importance-mark rule (first version flagged 70/70 entries). Treat *rates* measured on it as
provisional; the *mechanisms* are what transfer.

## Where to go next

1. **Recording is the only bottleneck left** (3/10, and it caps everything downstream). The
   signal-density ladder — hand-edit one view at ~10/30/60/90% signal and measure the recording
   rate — is the cheap experiment that would say whether the filler ratio is the cause, and it gives
   the fixture rebuild its requirement as a number. Single-pass cells, ~30 min.
2. **Importance marks at a scale that can emit them.** The mechanism is untested above 1.5B, and in
   the 35B-write configuration it is exactly the regime where it would matter.
3. **Phase 2 proper** — teacher regeneration on the pyramid + retrain — unchanged, still blocked
   behind the demand and fixture repairs, retrain still needs off-box GPU.
4. **M-NL G2 (oracle ceiling)** — untouched; still the gate separating "small models can't" from
   "the target is too subtle".
