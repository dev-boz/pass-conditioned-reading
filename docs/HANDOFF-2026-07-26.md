## Maintainer's observations, 2026-07-26 (drive the next instantiation)

1. **Treat total context like any other model's.** Input + output must fit. If the state is too big,
   we are asking for too much output, or the inputs are too big, or both. *Verified as a defect: the
   budget exists, is stated, is never enforced, and ran to 1.92×.*
2. **Were later passes ever given hints/scaffold?** Early passes should build empty tables, write
   "insert value here", and tell later passes where to look. Guided reading is the explicit form;
   there should be an **implicit** form baked into training. *Verified: it was never trained —
   1.8% / 1.3% / 0.03%.* **Synthesis: the protocol is REPLACE-biased, REPLACE needs a target, the
   scaffold passes never create one, so the REPLACE bias consolidates name-lists instead of filling
   slots. Placeholders are not a nicety here — the protocol's own mechanics require them.**
3. **Train the model to interpret the need by position.** "We need this information" should read as
   "…so on an early pass, record the table it lives in" vs "…so on a late pass, fill in the real
   value." Currently `need_class` is one constant string rendered identically at every pass;
   pass-conditioning is only `k/K` + stage rubric. *Cost note: unlike the data-first reorder, this
   cannot be a free re-render — changing the prompt invalidates the archived completions, so it
   needs new teacher generation.*
4. **Rare successes under adverse conditions are evidence of latent potential.** Adopted with a rule:
   an anomaly counts when the **mechanism reproduces under ablation**, not when the string appears
   once. The `distilled` probe qualifies (same state, same model, distractors removed → 2353);
   bare n=1 cross-family composes do not.

## 5. The diffusion framing (maintainer, end of session) — read this with observation 2

The first word in DiSCo is diffusion, and the maintainer's position is that this was the intent all
along: **the state's trajectory should look like a diffusion model's output** — junk and empty slots
early, resolving to clarity late. Masking is replaced by **compression**; latent state is replaced
by **disk state**. A native model would put the placeholders, tables and scaffold in latent space,
making the correspondence closer still.

**Why this matters operationally, not just rhetorically:** it recasts observation 2. Placeholders
are not a patch — **they are the noise**. A reverse process needs something to invert. The student's
state began as a *committed, low-entropy* inventory of names rather than *typed unresolved slots*,
so no denoising trajectory ever existed; the state simply accreted, 725 → 7,692 tok, monotonically.

**The consequence worth pursuing:** if compression is the corruption operator, the forward process
is **definable and cheap** — take a gold final state and progressively blank values into typed
placeholders (`23: 988` → `23: <cents>` → `REGION_SURCHARGE_CENTS: <table>` → absent). That yields
supervised pairs at every noise level **with no teacher rollout**. The current pipeline distills a
teacher *trajectory*: path-dependent, expensive, and — measured this session — it transmits whatever
idiosyncratic policy the teacher had (61.4% lossy summaries, 0.03% locator hints). A constructed
forward process is path-independent by construction. This is the concrete form of the "x̂₀ vs ε
prediction" point several gauntlet reviewers raised.

**Three falsifiable predictions, all cheap:**
1. State specificity should be **non-monotone** — placeholders rise, then resolve. Measurable on
   archived runs today; current runs should show flat accretion and no resolution phase.
2. Placeholders are **necessary, not optional**. The 0.03% rate is the accidental test; it failed.
3. Training should target **the state at level k**, not the edit sequence that produced it.

**Honest strain in the analogy, to state before a reviewer does:** diffusion's forward process is
stochastic and destroys information in a *known, simple* way, which is precisely why the reverse is
learnable. Compression is deterministic and semantically *selective* — it decides what matters — so
its inverse is a harder object. And DiSCo does two things at once: granularity refinement over the
same document (diffusion-like, Phase-A) and sequential coverage of different regions (filtering-like,
Phase-B, matching the Bayesian-filtering spine in `DISCO-NATIVE-ARCHITECTURE.md`). Be explicit about
which passes are which — they are not the same kind of step.
