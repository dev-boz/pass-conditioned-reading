## The wall, measured (why run-2 needs the 3070)

- Pascal (sm_61) has **no fused attention**: torch SDPA falls back to the math backend and
  materialises the n² score matrix **in fp32 for both dtypes** (half inputs upcast).
  Probes: fp32@8192, fp16@8192, fp16@10240 all OOM on the idle 11GB card.
- `train/chunked_attn.py` (flash-style online softmax, q-block nested checkpointing) fixes
  attention — **equivalence-gated**, run `~/e2prime-venv/bin/python train/test_chunked_attn.py`.
- fp32@10240 still OOMs after that: weights 6.2GB + boundary activations 1.8GB + the
  **LM-head logits path** ([1,10240,151936] fp32 = 6.2GB, plus transformers' CE fp32 copy).
  fp32@10K does not fit 11GB, period.
- CPU-only was estimated ~2–3 weeks (paper math, never measured; probe supports
  `... vram_probe.py 10240 fp32 stock cpu`) — shelved when the 3070 appeared.

## Run-2 on the 3070 — plan for the fresh session

3070 = Ampere sm_86: **flash/mem-efficient SDPA work, bf16 native** → the attention wall
is gone on that card. The 8GB catch: transformers still **upcasts full logits to fp32 for
CE** (~6.2GB at 10K seq × 152K vocab) — that alone breaks 8GB at ANY window ≥4K, so pick
one before launching:

1. **liger-kernel fused-linear-CE** (preferred: maintained library, chunks LM-head+CE,
   never materialises logits). Needs Triton to JIT → `sudo apt install gcc` in WSL first.

   pc_check.py also becomes unnecessary (it existed only because WSL had no C compiler).
   TRL SFTConfig has `use_liger_kernel=True`.

   works stock but Pascal layers bottleneck; last resort.

pre-registered fp32 default — record it as a D34 amendment when chosen; run-1's P-C

## Hazards learned this session (do not relearn these)

1. **transformers 5.x `apply_chat_template` returns a BatchEncoding dict** (not a tensor /
   id list). Bit this session TWICE (pc_check generate; a length-audit that reported every
   row <2048 and all slices "100% clean" — garbage). Always `return_dict=True` +
   `["input_ids"]`, and distrust any length stat that looks too good.
2. **TRL truncation is keep_start** — completions die silently. The length gate in
   train_lora.py is the permanent fix; never remove it.
3. **cp1252 stdout**: a `≥`/`→` in a print crashes redirected Windows output AFTER hours
   of work (pc_check wrote its JSON then died printing the verdict). ASCII-only in prints.
4. **MSYS/Git-Bash arg mangling**: python-launched Git ssh converts `~/...` remote args to
   the LOCAL home; fix = `MSYS_NO_PATHCONV=1` + `MSYS2_ARG_CONV_EXCL=*` in child env +
   home-relative remote paths (in `ClaudePClient`). Also `wsl.exe -- bash -lc '<script>'`
   mangles shell-variable assignments containing paths — inline absolute paths instead.
5. **Shell CWD resets** after compaction/resume: `cd /c/Users/Boz/pass-conditioned-reading`
   first, always.
6. **VRAM squatters**: llama-server holds ~4GB — stop it before training/probes; the
   desktop (Chrome/Steam) shares the 1080 Ti and caused run-1's step-228 OOM. Supervisor
   loop (wait-for-idle → launch → auto-resume on OOM, cap 20) is the pattern; checkpoints
   every 25 steps make crashes cost ≤25 steps.
7. **HF default eval batch is 8** → OOM at epoch boundaries; trainer now pins
   `per_device_eval_batch_size=1`.
8. **Probe before committing GPU-days**: `train/vram_probe.py <seq> <dtype> [chunked] [cpu]`.
9. Background monitors: offset-based tail (never re-grep old log content — a stale
   Traceback fires false alarms), `PYTHONUNBUFFERED=1`, ASCII filters, and remember
   monitor STALL thresholds must exceed the longest legitimate quiet period (eval ≈ 13 min).
